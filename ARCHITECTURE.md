## 1. Откуда требования: доска → компоненты

Единственный источник требований — фото доски. Каждая пометка на ней ложится на конкретный компонент:

| На доске | Что это значит у нас | Компонент |
|---|---|---|
| `siat.stat.uz`, `3000+`, `doc` | 3261 индикатор SIAT | Collector |
| `→ structured` | индикатор × элемент разреза (регион, отрасль…) × период → значение, плюс метаданные | Loader → SQLite |
| `txt` → поиск | названия на 4 языках, путь в каталоге, единицы — это то, *по чему ищем* | FTS5-индекс каталога |
| таблица → `db` | числа хранятся в SQL, их не режем на чанки | таблица `observation` |
| графики и карты (`img-to-text / tabular`) | на SIAT они рисуются из того же JSON, поэтому OCR не нужен. Храним данные плюс **ссылку на каждый вид визуализации** | provenance |
| `Embed → VDB, RAG` | семантический поиск не понадобился: полнотекстовый поиск находит нужный индикатор в top-5 на 21 из 21 тестового запроса | (later, если появятся промахи) |
| `+ MCP` | интерфейс, через который LLM работает с данными | MCP-сервер |
| `loop` | агентный цикл: модель вызывает инструменты, пока не соберёт ответ | MCP-клиент (Claude) |

## 2. Общая схема

```
                        ┌──────────────────────── ОФЛАЙН ─────────────────────────────────┐
                        │                                                                 │
 siat.stat.uz/api ──►  [1] Collector ──► [2] Raw store ──► [3] Loader ──► [4] SQLite      │
   (лимит 429)          siat-crawl        data/raw/*.json    siat-load      data/siat.db   │
                        (вежливый,        + crawl.sqlite     (нормализация,  + FTS5        │
                         докачка)                             без ПДн)                     │
        ▲                                                                       │         │
        └──── [7] Sync (запланирован): какие id обновились → снова [1]→[3]       │         │
                        └───────────────────────────────────────────────────────┼─────────┘
                                                                                ▼
                                                              [5] Core (Python-функции)
                                                         поиск · выборка · вычисления · source
                                                                                │
                                                              [6] MCP-сервер (stdio)
                                                                                │
                                                         Claude Code / Claude Desktop (агент)
                                                                                │
                                                              [8] Eval: вопросы с эталоном
```

Главный принцип: **числа считает код, а модель только выбирает инструменты и формулирует ответ.**

Каждое число, которое возвращает инструмент:
- взято из БД или посчитано кодом;
- снабжено блоком `source` со ссылкой.

> Важная оговорка: в режиме MCP финальный текст пишет модель-клиент, и наш сервер этот текст **не видит**. Поэтому проверить, что модель не исказила число в своём ответе, сервер не может. Гарантия сервера звучит так: «всё, что вернули инструменты, точно и со ссылкой». Итоговые ответы проверяет отдельный eval-прогон (§3, [8]).

## 3. Компоненты по слоям

### [1] Collector: скачивание (`siat-crawl`)

- **Что качаем:**
  - `GET /sdmx/json/` — дерево, 1 запрос;
  - на каждый из 3261 листьев три запроса: `/sdmx/{id}/` (карточка: `view_options`, `classifier`, `updated_xlsx`), `/sdmx/{id}/metadata/` и `/sdmx/{id}/table/`.
- **Объём:** ~9.8k запросов. Полный прогон занял около часа: ~2.7 запроса в секунду, ни одного `429`, 0 ошибок.
- **Вежливость:**
  - адаптивная пауза между запросами (старт 0.5 с, диапазон 0.3–6 с);
  - на `429` ждём `Retry-After` и замедляемся;
  - 5xx и сетевые ошибки повторяем с растущей паузой;
  - честный `User-Agent` с пометкой «учебный проект».
- **Докачка:** состояние каждого `(id, endpoint)` хранится в `data/crawl.sqlite`: статус, время, sha256 ответа. Если процесс прервался, повторный запуск продолжает с того же места (проверено на практике).
- Collector **ничего не знает о схеме БД**, он только сохраняет ответы как есть.

### [2] Raw store

- `data/raw/tree.json` и `data/raw/ind/{id}/card.json`, `metadata.json`, `table.json`. Это неизменённые ответы API, ~80 МБ.
- Зачем: БД можно пересобрать без повторного скачивания, всё воспроизводимо, есть что отлаживать.
- ⚠ В сырых файлах есть ФИО, телефоны и e-mail сотрудников. Поэтому `data/` исключена из git, а в БД, индекс и ответы эти поля не попадают.

### [3] Loader: raw → SQLite (`siat-load`)

- Парсит raw-файлы, нормализует и пишет в БД. Сборка идёт во временный файл, который в конце атомарно подменяет `siat.db`, поэтому сервер никогда не видит полусобранную базу.
- **Периоды:** `2025` → `Y`, `2025-Q3` → `Q`, `2025-M09` → `M`. Для каждого вычисляются `period_start` и `period_end`. Внутри одного ряда типы бывают смешаны (пример: id=3664), поэтому тип хранится в каждой строке. Неизвестные форматы получают тип `X` и хранятся как есть: на полных данных это учебные годы вида `2024/2025` (29 индикаторов, 2350 значений).
- **Метаданные** храним строками «ключ → значение». У разных индикаторов от 12 до 16 полей, порядок плавает, подписи различаются и бывают на узбекском. Ключ определяется по подписи через набор правил (`meta_keys.py`), сохраняется **только белый список**, остальное отбрасывается и считается в отчёте загрузки. Поля с ПДн отбрасываются всегда.
- **Флаги качества** — это **подсказки, а не факты**, так их и отдаём:
  - `table_empty`;
  - `has_zeros` — API прямо пишет в заголовке, что пропуски заменены нулями;
  - `cumulative_likely` — эвристика: значения растут внутри года и сбрасываются в начале следующего.
- **FTS5-индекс** каталога: названия на uz, uzc, ru и en, путь в дереве, код, единица, вид разреза и названия его элементов.
  - **Морфология.** Токенизатор **`trigram`** (поиск по кусочкам из 3 символов) плюс простое отсечение окончаний у слов запроса: «безработица» найдёт «безработицы», «браки» — «браков».
  - **Нормализация** одинаково для индекса и запроса: нижний регистр, все виды апострофов (`‘ ’ ʼ ' ʻ`) приводятся к одному, ё → е.
  - **Аббревиатуры** раскрываются до поиска: ВВП, ВРП, ИПЦ, YAIM, GDP, CPI…
  - **Ранжирование:** BM25 с весами колонок (совпадение в названии важнее, чем в пути или списке регионов), затем наверх поднимаются индикаторы, где слова запроса стоят в названии подряд.

**Итог полной загрузки:** 3261 индикатор, ~1.18 млн значений, 22 пустые таблицы, 308 рядов помечены как «вероятно нарастающим итогом», 9582 поля с ПДн отброшены.

### [4] SQLite: схема

Один файл `data/siat.db` (~139 МБ, в zip ~20 МБ), без сервера. Полный текст схемы — `src/siat/schema.sql`.

```sql
node(id PK, parent_id, code, level, is_leaf, position,
     name_uz, name_uzc, name_ru, name_en)                 -- дерево (разделы + индикаторы)

classifier(id PK, name_uz, name_uzc, name_ru, name_en)    -- вид разреза: Регионы, Вид деятельности,
                                                          -- Страны, Продукты, Возрастная группа…
indicator(id PK → node, code, classifier_id, periodicity_raw, view_options JSON, updated_xlsx,
          n_items, n_obs, period_types, first_period, last_period,
          table_empty, has_zeros, cumulative_likely, fetched_at)

indicator_meta(indicator_id, key, lang, value,            -- только белый список ключей:
               PRIMARY KEY(indicator_id, key, lang))      -- unit, periodicity, methodology, method_short,
                                                          -- methodology_url, note, info_source, org_name,
                                                          -- classifiers, department… (без ПДн)
item(indicator_id, code, position, is_root,               -- строки таблицы = элементы разреза
     name_uz, name_uzc, name_ru, name_en,                 -- (для Регионов code = СОАТО: 1700, 1735…)
     PRIMARY KEY(indicator_id, code))

observation(indicator_id, item_code, period /*исходная строка*/, period_type /*Y|Q|M|X*/,
            period_start, period_end, value REAL,
            PRIMARY KEY(indicator_id, item_code, period))

catalog_fts  -- FTS5(tokenize='trigram'): названия ×4 языка, путь, код, единица, разрез (нормализованные)
load_info(key, value)                                     -- дата снимка, счётчики, отчёт загрузки
```

Две находки, которые определили схему:

- **Строки таблицы — это не всегда регионы**, а элементы **классификатора** индикатора (на сайте колонка «Разрез»): Регионы (~85%), Вид деятельности (ОКЭД A, B, C…), Страны, Продукты, Возрастная группа и др. Поэтому схема хранит общий «разрез» (`item`), а регион — его частный случай.
- **Метаданные грязные:** один и тот же ключ называется по-разному (`Номер телефона :` / `Номер телефона:`), ключи бывают на узбекском, ФИО встречается даже в имени ключа. Отсюда белый список вместо фиксированных колонок.

### [5] Core: общие функции (`core.py`, `provenance.py`)

Это обычные Python-функции, которые ничего не знают про MCP. Их можно тестировать без LLM.

- `search(query, lang, section_code, periodicity, limit)` → карточки индикаторов; точное совпадение по id или коду идёт первым.
- `browse(code)` → дочерние узлы каталога.
- `get_indicator(ref)` → метаданные, элементы разреза, периоды, предупреждения, источник.
- `get_data(ref, items, period_from, period_to, period_type)` → таблица «элемент × период».
- `rank_items(ref, period, order, top)` → рейтинг с долями от итога.
- `compute_change(ref, item, period_from, period_to)` → абсолютное и процентное изменение, среднегодовой темп.
- `build_source(...)` → блок источника (§5).

### [6] MCP-сервер (`server.py`)

- Официальный Python SDK **`mcp` 2.x** (2.3.0): `from mcp.server import MCPServer`.
- Транспорт: **stdio**. Клиент сам запускает сервер как подпроцесс; в stdout пишет только протокол, логи идут в stderr.
- Соединение с БД открывается на каждый вызов, поэтому загрузчик может подменить `siat.db`, не останавливая сервер.
- Вывод каждого инструмента двойной:
  - компактный JSON-текст — для модели;
  - тот же объект в `structuredContent` — для программ.
- Ожидаемые ошибки (не найдено, неверный формат периода) возвращаются модели понятным текстом с подсказкой, что делать дальше.
- Все инструменты помечены как read-only (`readOnlyHint`): они ничего не меняют.

### [6b] Инструменты разработчика

- **MCP Inspector** (`uv run mcp dev src/siat/server.py`) — «Swagger для MCP»: список инструментов, их схемы, ручной вызов в браузере.
- **Смоук-тест** (`scripts/smoke_mcp.py`): настоящий MCP-клиент запускает сервер и вызывает все инструменты.
- REST API + Swagger решили не делать: работаем только через MCP.

### [7] Sync: обновление данных (запланирован, не реализован)

- Читать `/announcements/` до последней обработанной даты, доставать из HTML-ссылок `reports-filed/{id}/` id индикаторов и перекачивать их через [1]→[3].
- Раз в неделю сверять `updated_xlsx` из дерева `/sdmx/json/` (поле есть у каждого листа — проверено) с БД, чтобы поймать то, что лента пропустила.
- Сейчас обновление делается вручную: `siat-crawl --force` и `siat-load`.

### [8] Eval: проверка качества

| Уровень | Что | Как запустить | Результат |
|---|---|---|---|
| 1. Код | 20 тестов: периоды, ключи метаданных, отсутствие ПДн, поиск, выборка, рейтинг, изменение, ошибки — на искусственном наборе данных | `uv run pytest` | 20/20 |
| 2. Поиск | 21 запрос на ru / uz / en, в разных падежах и с аббревиатурами | `uv run python eval/search_check.py` | top-1: 20/21, top-5: 21/21 |
| 3. Ответы модели | 40 вопросов, эталон генерируется из БД: значение, лидер, изменение в %, вопрос-ловушка про год без данных | `eval/make_questions.py` → ответы модели → `eval/grade.py` | 40/40 верных, 40/40 со ссылкой |

Уровень 3 прогонялся вручную: отдельная сессия Claude Code с подключённым сервером отвечала на вопросы из `eval/questions.jsonl`, эталон лежит отдельно в `data/eval/gold.jsonl`. `grade.py` сверяет числа (допуск 0.1%), название лидера с учётом падежей, честный отказ на вопросах-ловушках и наличие ссылки на нужный индикатор. Сам скрипт проверки проверен на поддельных ответах с подложенными ошибками.

Ограничение: вопросы шаблонные и содержат точное название индикатора. Следующий шаг — вопросы, сформулированные «как спросил бы человек».

## 4. Инструменты MCP (контракты)

| Tool | Вход | Выход | Ограничения |
|---|---|---|---|
| `search_indicators` | `query` (любой из 4 языков), `section_code?`, `periodicity?` (`year`/`quarter`/`month`), `limit≤20` | `[{id, code, name, path, unit, periodicity, breakdown, n_items, periods:[from,to], updated}]` | только каталог, без чисел |
| `browse_catalog` | `code?` (пусто — корень) | дочерние узлы | для навигации по дереву |
| `get_indicator` | `indicator` (id или код) | метаданные, элементы разреза (до 80), периоды по типам, предупреждения, `source` | без ПДн |
| `get_data` | `indicator`, `items?` (коды или части названий: «Самарканд»), `period_from?`, `period_to?`, `period_type?` | строки + `unit`, `period_type`, `warnings`, `source`, **`truncated`** | ≤ 500 значений; если больше — остаются последние периоды и ставится `truncated: true` с подсказкой сузить запрос; **один тип периода на ответ** |
| `rank_items` | `indicator`, `period?` (пусто — последний), `order`, `top?` | рейтинг элементов разреза + итоговая строка + `source` | доли от итога считаются, только если части в сумме дают 80–102% итога; если меньше 98% — предупреждение |
| `compute_change` | `indicator`, `period_from`, `period_to`, `item?` (пусто — итоговая строка) | абсолютное изменение, %, среднегодовой темп (для годовых рядов) + `source` | предупреждения: нарастающий итог, разные типы периодов, показатель уже в % |

Правила для всех инструментов:
- у каждого есть параметр `lang` (`ru` | `uz` | `uzc` | `en`, по умолчанию `ru`): на этом языке возвращаются названия и ссылки;
- в каждом ответе с числами есть единица измерения, предупреждения (ноль может значить «нет данных», ряд нарастающим итогом) и `source` (§5);
- ошибки возвращаются понятным текстом с подсказкой, например: «индикатор не найден — используй search_indicators».

**Resource:** `siat://indicator/{id}` — карточка индикатора в JSON (то же, что `get_indicator`).
**Prompts:** `regional_comparison(topic, year)`, `trend_analysis(topic, region)` — готовые сценарии для пользователя.
**Instructions** сервера говорят модели порядок работы (найти → посмотреть карточку → взять числа) и правила ответа: числа только из инструментов, `citation` дословно, учитывать предупреждения, при отсутствии данных так и сказать.

## 5. Provenance: ссылка на источник у каждого числа и визуализации

Ссылок два вида, оба проверены:

**1. Основная ссылка-цитата:** `https://siat.stat.uz/data/{id}/?lang=ru|uz|uzc|en`.
- Статическая страница, которую сервер сайта отдаёт сразу готовой, без JavaScript.
- На ней на нужном языке есть название, код, дата «Обновлено» и **полная таблица** значений.
- Для цитаты подходит лучше всего: открывается у любого и показывает ровно те числа, что у нас.

**2. Ссылки на конкретные визуализации** в интерактивном интерфейсе. Шаблон URL взят из JS-кода сайта. Язык эти страницы берут из настроек браузера.

```
https://siat.stat.uz/reports-filed/{id}/{slug}
```

`slug` берётся из `view_options` конкретного индикатора:

| view_options | slug в URL | что это |
|---|---|---|
| metadata | `meta-data` | метаданные |
| table | `table-data` | таблица |
| graphics | `line-data` | линейный график |
| gistogram | `bar-data` | гистограмма |
| cartogram | `map-data` | карта |
| rating | `rate-data` | рейтинг регионов |
| compare_regions | `compare-data` | сравнение регионов |
| comparative_ratio | `relationship-data` | соотношение |
| customization | `custom-data` | конструктор |

Блок, который возвращается вместе с данными (реальный ответ для ВРП; `views` содержит только те виды, что есть у индикатора):

```json
"source": {
  "publisher": "Национальный комитет Республики Узбекистан по статистике",
  "primary_source": "Данные отчетности и статистического обследования, административные данные",
  "indicator_code": "1.01.03.0001",
  "indicator_name": "Объем валового внутреннего (регионального) продукта (годовые)",
  "unit": "в текущих ценах, млрд cум",
  "url": "https://siat.stat.uz/data/1299/?lang=ru",
  "views": {
    "metadata":  "https://siat.stat.uz/reports-filed/1299/meta-data",
    "table":     "https://siat.stat.uz/reports-filed/1299/table-data",
    "graphics":  "https://siat.stat.uz/reports-filed/1299/line-data"
  },
  "api": "https://siat.stat.uz/api/sdmx/1299/table/",
  "source_updated": "2026-11-13",
  "snapshot_date": "2026-11-19",
  "citation": "Источник: SIAT (siat.stat.uz), «Объем валового внутреннего (регионального) продукта (годовые)», код 1.01.03.0001, данные обновлены 2026-11-13. https://siat.stat.uz/data/1299/?lang=ru"
}
```

Строку `citation` модель вставляет под ответом или графиком как есть, без пересказа. Блок собирает код, поэтому модель не может «придумать» ссылку.

Правила заполнения:
- `publisher` и `primary_source` берутся **из метаданных каждого индикатора**, а не из константы: источники бывают разные;
- `source_updated` — всегда `updated_xlsx`, ровно эту дату сайт показывает как «Обновлено». Дата «последнего изменения» в метаданных бывает другой, у одного индикатора расхождение было в полгода;
- `snapshot_date` — когда данные скачаны к нам.

## 9. Что не входит в v1 (later)

- **Sync** по `/announcements/` и еженедельная сверка `updated_xlsx` (§3, [7]).
- **Экспорт** датасета в Parquet/CSV как отдельный «structured»-результат.
- **Сложный eval:** вопросы своими словами, без точного названия индикатора; автоматический прогон через Anthropic API.
- **Индикаторы-близнецы:** 37 названий встречаются в разных разделах (75 индикаторов). Стоит показывать в выдаче поиска, что у индикатора есть близнец.
- **Векторный или гибридный поиск** — если сложный eval покажет промахи полнотекстового поиска.
- **Разбор разрезов из названий** (пол, возраст, город/село) в отдельные поля.
- **PDF-методики с lib.stat.uz** (здесь мог бы пригодиться img-to-table). Сайт блокирует не-браузерные запросы, это нужно согласовывать отдельно.
- **Районы:** у части индикаторов есть флаг `show_districts`, но эндпоинт с районными данными не найден.
- **HTTP-транспорт MCP** и деплой на сервер — чтобы подключаться из браузерного claude.ai.
- **Рендер графиков** внутри MCP. Пока отдаём данные и ссылку на график сайта, нарисовать по данным может сам клиент.

## 10. Риски

| Риск | Что делаем |
|---|---|
| Лимит 429 / блокировка | адаптивная пауза, `Retry-After`, raw-кэш (повторно качать не нужно) |
| API без документации может поменяться | raw store + тесты Loader; при поломке видно, где именно |
| Ноль вместо пропуска | флаг + текст предупреждения в каждом ответе |
| Кумулятивные ряды | эвристика + предупреждение; `compute_change` не суммирует периоды |
| Модель исказит число в финальном тексте | готовая строка `citation`, компактные ответы, eval уровня 3 |
| ПДн в метаданных | белый список в Loader, проверка тестом, `data/` не в git |
| Данные устаревают | `source_updated` и `snapshot_date` в каждом ответе; sync — в планах |
